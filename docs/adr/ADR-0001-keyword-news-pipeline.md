# ADR-0001: 국가별 대량 경제뉴스 기반 키워드 파이프라인 / 国別大量経済ニュースに基づくkeyword pipeline

- 상태 / 状態: Accepted
- 결정일 / 決定日: 2026-08-06
- 관련 명세 / 関連仕様: `PROJECT_SPEC.md`, `PROJECT_SPEC_JA.md`

## 한국어

### 배경

기존 운영 소스는 중앙은행·정부기관 RSS 중심이어서 국가별 하루 기사량이 적고 일반 경제언론의 공통 관심사를 대표하지 못했다. 사용자가 원하는 결과는 기관 발표 요약이 아니라, 각국 경제뉴스 100건 이상에서 반복 출현한 단어·복합명사 TOP 5와 키워드별 관련 기사다.

### 결정

1. GDELT DOC API Article List를 미국·일본·한국의 주 뉴스 metadata 소스로 사용한다.
2. 국가별 중복 제거 후 150건을 목표로 하고 최대 250건, 권장 수집 100건 이상, 게시 하한 70건, 부분 성공 50~69건으로 제한한다.
3. 기존 중앙은행·정부 RSS와 BEA·e-Stat 같은 공공 API는 보조 소스로 유지한다.
4. 기사 본문을 crawl·저장하지 않고 제공된 제목·짧은 요약·URL·매체·시각만 사용한다.
5. 영어·일본어·한국어별 분석기가 반복 명사와 최대 2개 형태소의 짧은 복합명사를 추출하고 국가별 불용어와 문장 조각을 제거한다.
6. 동일 기사의 반복 출현은 한 번만 계산하며, 고유 기사 문서 빈도를 우선하고 매체 다양성·최신 시각·ID로 동률을 해소한다.
7. LLM은 입력 후보 안에서 동의어·표기 변형과 1~3단어 표시명을 통합할 뿐 후보 생성이나 순위 결정은 하지 않는다.
8. TOP 5 키워드는 근거 표현과 관련 기사 최대 20개를 제공한다.
9. 기존 v1 필드 의미를 바꾸지 않고 키워드 계약을 Schema 2.0, `/api/v2`, `data/v2`로 추가한다.

### 결과와 트레이드오프

- 기사 표본과 매체 다양성이 늘어 사용자가 기대한 “그날 많이 등장한 경제 키워드”에 가까워진다.
- 국가별 query와 불용어가 편향을 만들 수 있으므로 version·수집량·표본 품질을 기록하고 fixture 회귀 검증을 수행한다.
- 형태소 분석 의존성과 v2 migration 작업이 추가되지만, 결정적 순위와 관련 기사 근거를 유지해 설명 가능성을 높인다.
- GDELT 가용성이나 포괄 범위가 변할 수 있으므로 기존 RSS adapter와 DataSource 경계를 유지한다.

### 구현 순서

1. GDELT adapter·국가별 query config·100건 이상 fixture
2. 중복 제거와 매체 편중 제한
3. 언어별 후보 추출·불용어·복합명사 검증
4. 제한적 LLM 통합과 결정적 순위
5. Schema/API/DataSource v2와 관련 기사 UI
6. live 표본 품질·비용·성능 검증 후 운영 전환

2026-08-08 실제 표본에서 제목 앞부분이 문장 조각으로 노출되는 한계가 확인되어 한국어는 `kiwipiepy`, 일본어는 `SudachiPy` core 사전, 영어는 정규화 단어·2단어 규칙으로 교체했다. 한 제목에서 여러 후보를 만들되 하나의 단어 또는 최대 2개 형태소의 짧은 이슈 개념만 허용한다. 후보는 최소 3개 기사 또는 전체의 3% 중 큰 값과 서로 다른 2개 매체를 충족해야 한다. 국가별 120건 fixture에서 짧은 TOP 5, 일반어·문장 조각 제외, 결정성, 원문 근거와 관련 기사 최대 20건을 회귀 검증한다.

2026-08-09 실제 예약 실행에서 US 198건·JP 103건·KR 85건이 확보됐지만 기존 100건 게시 게이트로 결과가 폐기됐다. 무료 소스의 일별 변동을 수용하면서 TOP 5 품질 조건을 유지하기 위해 수집 목표는 그대로 두고 세 국가의 실제 게시 하한만 각각 70건으로 낮춘다.

## 日本語

### 背景

既存の本番sourceは中央銀行・政府機関RSS中心で、国別の日次記事数が少なく、一般経済報道の共通関心を代表できなかった。利用者が求める結果は機関発表の要約ではなく、各国の経済ニュース100件以上から反復出現する単語・複合名詞TOP 5とkeyword別関連記事である。

### 決定

1. GDELT DOC API Article Listを米国・日本・韓国の主news metadata sourceとして使う。
2. 国別重複排除後150件を目標、最大250件、推奨収集100件以上、配布下限70件、部分成功50～69件とする。
3. 既存中央銀行・政府RSSとBEA・e-Statなどの公共APIは補助sourceとして維持する。
4. 記事本文をcrawl・保存せず、提供title・短いsummary・URL・媒体・時刻だけを使う。
5. 英語・日本語・韓国語別分析器が反復名詞と最大2形態素の短い複合名詞を抽出し、国別stopwordと文断片を除外する。
6. 同一記事内の反復出現は一度だけ数え、ユニーク記事のdocument frequencyを優先し、媒体多様性・最新時刻・IDで同順位を解消する。
7. LLMは入力候補内で同義語・表記揺れと1～3語の表示名を統合するだけで、候補生成や順位決定を行わない。
8. TOP 5 keywordは根拠表現と関連記事最大20件を提供する。
9. 既存v1 field意味を変更せず、keyword契約をSchema 2.0、`/api/v2`、`data/v2`として追加する。

### 結果とtrade-off

- 記事sampleと媒体多様性が増え、利用者が期待する「当日多く登場した経済keyword」に近づく。
- 国別queryとstopwordが偏りを生む可能性があるため、version・収集量・sample品質を記録しfixture regressionを行う。
- 形態素分析依存とv2 migration作業が増えるが、決定的順位と関連記事根拠を維持して説明可能性を高める。
- GDELTの可用性・coverage変更に備え、既存RSS adapterとDataSource境界を維持する。

### 実装順序

1. GDELT adapter・国別query config・100件以上fixture
2. 重複排除と媒体偏重制限
3. 言語別候補抽出・stopword・複合名詞検証
4. 制限付きLLM統合と決定的順位
5. Schema/API/DataSource v2と関連記事UI
6. live sample品質・費用・性能検証後に本番移行

2026-08-08の実sampleでtitle先頭部分が文断片として表示される限界を確認し、韓国語は`kiwipiepy`、日本語は`SudachiPy` core辞書、英語は正規化単語・2語規則へ置き換えた。一つのtitleから複数候補を生成するが、一単語または最大2形態素の短いイシュー概念だけを許可する。候補は最低3記事または全体の3%の大きい方と、異なる2媒体を満たす必要がある。国別120件fixtureで短いTOP 5、一般語・文断片除外、決定性、原文根拠、関連記事最大20件をregression検証する。

2026-08-09の実予約実行ではUS 198件・JP 103件・KR 85件を確保したが、従来の100件配布gateにより結果が破棄された。無料sourceの日次変動を許容しながらTOP 5品質条件を維持するため、収集目標は維持し、3か国の実配布下限だけを各70件へ下げる。
